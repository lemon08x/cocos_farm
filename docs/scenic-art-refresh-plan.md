# 田园场景美术重制：具体方案与素材 agent 交接

日期：2026-09-29。实现基线：`889a994`。状态：**待实施方案**；本文件不代表新素材、预览工具或渲染修正已经完成。

本轮目标：消除满屏细碎草纹、重复拼块和功能占位感，在保留现有玩法与图块几何的前提下，做出主体清楚、植被有疏密、材质统一的手绘农场。优先实现“农舍—院落—田地”的视觉关系，再扩展全套素材。

## 1. 执行入口与范围

图片生成 agent 以本文件为本轮任务入口，结合 [独立风格包流程](scenic-style-packs.md) 执行命令，以 [tile-art.ts](../core/src/game/scene/tile-art.ts) 为尺寸、接口、锚点的唯一依据。旧 [首批生成要求](tile-art-generation-requirements.md) 只用于追溯，不能沿用其“先生成全部、最后才看整体”的工作顺序。

本轮采用独立风格 ID **`pastoral-soft`**，显示名 **`田园 · 柔绘`**。沿用原手绘田园方向，降低背景纹理密度、统一物件笔触，不改成像素画或写实摄影。保留 `pastoral` 和所有旧原稿；新风格保持 `linear` 过滤。

工作分两项，交付报告必须分别说明完成情况：

| 工作项 | 执行内容 | 完成边界 |
|---|---|---|
| A：素材重制，本轮图片 agent 执行 | 独立风格配置、50 张源图、来源记录、拼接预览、完整导入、发布、实际游戏核对 | 能在设置中选择新包；不宣称同时解决全部界面问题 |
| B：呈现修正，后续代码任务 | 未知区域、文字牌、选择反馈、边缘覆盖、必要的物件扩展和场景布置 | 按第 7 节实施并单独验证；不能靠改 PNG 冒充完成 |

保留地块 ID、四边端口、道路/河流拓扑、探索与水利规则、存档、物件占地。新增风格先供选择，不擅自改默认包或删除用户进度。

## 2. 问题与对应修改

| 已观察到的问题 | 修改方法 | 如何判断有效 |
|---|---|---|
| 草地黄绿色亮点和细草铺满屏幕 | 重生草地及全部公共母版，改成连续色面、局部草簇 | 正常镜头下地面平静，田地和物件先被看见 |
| 草地变体仍像重复壁纸 | 三种变体保持相同底色与明暗范围，只改变内部柔和斑块和少量草簇位置 | 连续铺图既不出现重复徽记，也不出现深浅棋盘格 |
| 道路机械、转角生硬 | 端口保持不变，单元内部柔化路肩与转弯，减少等宽硬线和均匀碎石 | 道路连通清楚，接口不产生突变；不承诺贴图能改变路径走向 |
| 建筑、树、地面细节尺度不同 | 用同一套目标参考、色板和材质样板生成，物件以大形和成组笔触为主 | 房屋不会像照片贴在插画草地上，树叶不退化成噪点 |
| 地块之间过空、零散物件缺少组织 | A 先改善地面与院落关系；B 再在合法环境位置增加成组装饰 | 不靠每张草图都画花丛来填满空地 |
| 浅色实心菱形、泉眼文字牌、粗选中框 | 修改渲染与状态映射，详见第 7 节 | 状态仍可读，地图不再像编辑器占位展示 |
| 截图顶部黑色缺口 | 复现后区分数据覆盖、裁剪、透明缺口与地图外部背景 | 修复根因；目前不能仅凭截图断定原因 |

当前包采用 600×360 地面源图、300×180 显示规格和线性过滤。提高分辨率或切换过滤方式不是本轮主要修复手段。

## 3. 统一美术标准

### 3.1 参考与目标构图

实际打开 [原田区浏览参考图](../art/expansion-previews/02-district-browse.png)。保留其农舍、田地、河流与成组植被的组织关系，以及暖土色、青绿色水面和柔和手绘形体；**不要照搬参考图中同样密集的细草、花点和全屏细节**。旧草地只能作为问题对照，不能继续作为新包材质基准。

先制作一张无文字、无 UI 的目标场景参考，保存到新风格的 `generation-records/references/target-scene.png`，明确标为概念参考。它应表现一个农舍院落、相邻田地、一段道路及局部植被，采用与游戏相容的等距视角。建筑、作物、地面都有接地关系，不画悬浮地台。

目标画面中有细节集中区域，也有平静区域：农舍和耕作区承担主体，背景草地退后；不要把整幅画降成灰蒙蒙的一片。允许局部明亮花色和成熟麦穗，但不把亮点均匀洒满所有地面。

### 3.2 各类素材的可执行要求

| 类型 | 具体要求 | 禁止或需返修的表现 |
|---|---|---|
| 草地与母版 | 大部分面积为低对比连续色面；少量宽笔触草簇；三个变体共享底色和明暗 | 每根草都清晰、密集黄色高光、平铺花点、中心固定徽记、菱形边缘亮环 |
| 土路 | 暖灰土色，内部略有不规则磨损；草与土在路肩柔和过渡；端口附近收敛到同一宽度和材质 | 硬描边、整条等距碎石、路口断开、用旋转图补另一方向 |
| 干湿田 | 两图共用耕作区、田埂和行向；湿田通过土色和局部柔光区分；耕作面视觉面积明显大于草边 | 两种状态田块形状变化、黑色厚台、土壤颗粒比幼苗抢眼 |
| 院落 | 简洁夯土地与少量大块铺石，与房屋落点协调，外缘过渡到新草地 | 自带另一栋房屋、围栏/树占据不可控位置、满地细碎石子 |
| 河流与桥 | 水面以连贯青绿色块和少量反光表现；河岸简化；桥板按整体结构分组 | 密集白色波点、两岸材质不一致、桥头错口、平面旋转导致光照反转 |
| 树与农舍 | 统一左上光、右下短影；树冠以叶团组织；屋面/墙面保留大面和有限结构细节 | 每片叶独立描边、照片锐度、过重黑边、附带矩形或菱形底板 |
| 作物 | 幼苗和成熟期共用株位、行向和根部；轮廓清楚，行间透明 | 幼苗提前长麦穗、成熟期换种植位置、整片不透底、带土层 |

“大部分平静、局部细节”是绘制指导，不是自动评分阈值。禁止通过模糊滤镜处理整张旧图来代替形体和细节密度的重制。

### 3.3 风格配置与提示词

先初始化（已有该目录时读取并继续，不覆盖）：

```powershell
npm run tiles:style -- init pastoral-soft --name "田园 · 柔绘"
```

在生成正式图块前填写并固定 `art/scenic/styles/pastoral-soft/style.json`：

- `status: "draft"`，`textureFilter: "linear"`，保留完整 22 项 palette。
- `generation.references` 包含原参考图和新目标场景参考的仓库相对路径。
- `generation.description` 使用下面的共同要求；`generation.negative` 写入明确排除项。
- 色板建议起点：草地中间色 `#839765`、暗部 `#617650`、土路 `#C4AD83`、干土 `#937154`、水面 `#729E98`、纸面 `#F5F0E3`、文字 `#29473C`。这些是材质协调参考，不把所有像素量化到这几个颜色；其余 UI 和小地图色键一起核对可读性。

共同正向要求：

> 柔和水粉与手绘田园插画，等距农场游戏素材。优先清晰大形、成组笔触和疏密变化。背景地面以低对比连续色面为主，草簇只在少量局部出现；主体农舍、树木与作物的轮廓比地面纹理清楚。统一左上光照、右下短而柔和的阴影，统一物体比例与笔触尺度。使用附带目标场景图作为色彩和形体参考，遵守当前 control/guide 的几何、端口和落点。以实际游戏缩放后的组合效果判断，不追求放大原图时每一处都很精细。

共同排除项：

> 不要像素画、照片质感、密集细草、均匀黄白亮点、颗粒噪声、锐化边缘、满屏等量细节、固定中心花纹、黑色描边、浮空厚土台、四周暗角、烘焙文字/UI、棋盘格背景。不要把草地画成植物主体特写。

草地专项追加：

> 这是可重复拼接的背景地面，不是草丛插画。保持宽阔、平静的绿色底面，用少量柔和色差表达地表起伏。局部草簇简化为成组笔触，避免独立草叶充满菱形。三个变体保持相同平均明暗与色温，细节位置不同。边缘及顶点必须与本风格公共母版一致，不画边框或亮环。

每次调用还要附上该 ID 的几何提示词、control/guide 和相关邻件参考。文字里提到参考路径不等于工具已收到参考图片。不要让生成模型绘制 guide 的线、标签和示意色。

先生成目标场景参考和少量草地/路面材质研究图，不计入正式任务数量。确定方向后完成 A0，再让 A1 内部材质贴合母版。不要先批量生成 43 张内部图，最后才补接缝。

几何摘要（具体 job 优先）：地面和作物 600×360；草地菱形内填满、外透明；作物仅植物、不含地面；树 600×720，根部 `(300,540)`；房屋 1200×1080，落点 `(600,540)`；母版 352×96，顶点 80×80，均不透明。路口占边长 24%，水口 40%；各方向独立生成，不旋转带光照图片。

本轮所有 7 张母版重新制作。旧树/房屋只有在笔触和细节尺度相容时才可编辑复用，不能因为透明度校验通过就直接沿用。旧干湿田可作结构参考，不混入旧草地外圈。复用必须保留来源及处理记录。

## 5. 样板检查与实际游戏验证

### 5.1 A1 完成后先检查组合，再扩展 A2

当前 `tiles:import` 必须 50 项齐全；**没有局部导入或局部运行时发布功能**。A1 阶段不能设 `ready`，不能复制旧图凑数发布，也不能修改导入校验让半包通过。

由执行 agent 制作一个小型预览脚本，建议保存为新风格 `generation-records/make-preview.mjs`。复用 `tools/tile-art-lib.mjs` 的 `contract()`、`jobsFor()`、`validateSource()`、`composeGround()`：校验已有源图，用本包 7 张母版合成已有地面，再按契约中心位置和物件锚点组合。脚本只产出素材预览，不修改正式 manifest，不另写一套接缝算法。

固定输出以下组合：

1. 至少 5×5 连续草地，三个变体混排，检查重复图案、明暗棋盘格、顶点星状痕迹及接缝亮环。
2. 道路直线、转角、交叉口组合，检查端口、路肩、转角过渡；待 A2 完成后补充河流转角/桥组合。
3. 农舍、院落、树、空田和幼苗的局部样板，不通过摆放模型未生成的成熟田地来虚构新局效果。

每组保存源分辨率检查图和按运行时尺寸缩小的图；地面先按 300×180，再按实际镜头 zoom 缩放，避免只看高清原图。样板文件标明“素材拼接预览，非游戏截图”。读取当前游戏镜头或记录采用的镜头比例，不能将世界显示尺寸误当最终屏幕像素尺寸。

检查由 agent 自主进行，不要求用户逐图确认，不建立自动审美评分系统。发现满屏噪点、显著拼块或主体不清时，回修草地/母版及关联素材，再继续 A2。记录问题和修改结果；不能用一次技术导入成功替代视觉检查。

### 5.2 全包发布后的实际运行核对

完整包发布后，在游戏设置中选择 `pastoral-soft`，沿用同一存档、同一镜头、同一选中地块拍摄旧/新对比。至少保存：

- 默认农舍视角：HUD 下的主体关系、空田和院落可读性。
- 实际存在的道路/河流/桥连接位置：材质和接缝。
- 一处已知/未知交界，以及允许缩放范围内的近景、远景：重复纹理、边缘与状态可读性。

同场景比较需记录视口尺寸、镜头坐标/zoom、风格 ID/manifest revision；截图要显示真实游戏状态。没有合法成熟作物时，用标明的素材预览检查成熟图，不篡改用户存档、跳过农时或把测试状态说成正常新局。

如执行环境没有可运行的 Cocos/Web 构建，可以交付完整素材和发布结果，但报告必须注明“实际游戏视觉未验证”，不能声称完成这一步。已有构建可通过发布/热加载看纯素材变化；不为每张图片重复构建游戏。

## 6. 命令、来源记录与发布

目标参考及风格配置确定后执行：

```powershell
npm run tiles:prepare -- --style pastoral-soft
npm run tiles:status -- --style pastoral-soft

# 对每个 ID 使用其真实文件路径，必要时附明确 --crop x,y,width,height。
npm run tiles:normalize -- grass.0 "C:\art\grass.png" --style pastoral-soft --generator "实际工具及模型"

# 50 项齐全后导入；不要在 A1 阶段执行发布。
npm run tiles:import -- --style pastoral-soft
```

每个 ID 保存真正的 AI 原稿、实际提示词、参考输入列表、工具/模型、裁剪/抠图/合成步骤和可复现脚本。模型名称未暴露则如实写明，不伪造来源。`raw/` 备份 normalize 输入，不能替代加工前原稿。不要使用过期临时 URL 或本机临时目录作为唯一交付。

修改 generation 配置后重新 prepare，并按工具要求重新登记受影响图片；母版变化后重新合成和复查所有相关地面。不得修改哈希、放宽 alpha 检查或以模板代替正式美术。

完整导入成功后，将新风格 `status` 改为 `ready`，执行：

```powershell
npm run tiles:publish
```

发布后核对风格目录、实际运行截图和报告。交付 `art/scenic/styles/pastoral-soft/GENERATION-REPORT.md`，含逐 ID 的生成/复用说明、源图及记录路径、A1 发现与修正、导入/发布结果、游戏视觉验证情况、未完成项。保留 Git 可追踪的源图、原稿、记录、预览脚本及必要截图，不只交付被忽略的 `build/` 目录。

## 7. 必须配合的呈现修改（后续代码任务）

本节是明确的待实施清单，不要求图片 agent 为现阶段不受支持的槽位先生成素材。优先修边缘覆盖和雾，再做物件扩展与布局细化。

| 优先级 | 修改位置 | 具体实现要求 | 验证方式 |
|---|---|---|---|
| P0 | `ScenicWorldView.ts` 的地面层及场景背景；`core/src/game/scene/world.ts` 的覆盖数据；镜头限制 | 复现黑色缺口：记录镜头/视口，核对缺口处是否有 region、有纹理、被裁剪或在地图外。缺 region 修环境覆盖，错误裁剪按图片边界修可见性；有限地图外使用与风格一致的背景和边缘过渡，不创建可探索假地块。背景色随风格切换更新，不能只涂色掩盖内部漏格 | 原缺口镜头、四个边界、远近缩放、切换风格均核对；地块集合和存档不变 |
| P1 | `ScenicWorldView.ts` 的 fog 层 | 将逐格高不透明度实心菱形改为统一的未知区域遮罩：相邻未知格合并内边界，在外轮廓做有限宽度羽化；孤立未知格也柔化外缘。未知内部保持遮挡，羽化向已知/环境侧展开，不泄漏资源；沿道路分开的未知区域不能为美观强行连成一片 | 未知类型不泄漏，已知田地和必要道路不被遮住；探索后局部正确刷新，命中边界仍读 scene |
| P1 | `ScenicWorldView.ts` 的 `badge()`、`drawSelection()`；田况面板 | 有物件表现后取消对应常驻文字牌，名称放选中反馈/田况面板；尚无素材的状态仍保留必要标识。选中轮廓用随 zoom 补偿的细线，建议以约 2 个 UI 逻辑像素为起点，减少双重粗框；不改变点击范围 | 选择、施工、用途、设施状态均可获知；远近缩放仍可见，不能把缺物件变成无提示 |
| P2 | `tile-art.ts`、生成/发布工具、`ScenicStyleContract.ts`、`ScenicWorldView.ts` | 第二批优先扩展泉眼、石地、灌木、花簇的专用槽位。先定义画布/锚点/层级、状态映射和旧包兼容路径，再下发图片任务。地面型泉眼需包含合法基底或明确透明覆盖语义，不把环境河源当成已发现可用泉眼 | 旧包仍可加载，新物件随公开状态刷新，未知区域不提前显示；缺专用素材时有明确回退 |
| P2 | `core/src/game/scene/world.ts` 的对象快照和已有环境布局；`ScenicWorldView.ts` 的深度层 | 在农舍边、院落角、田边成组放置装饰，并留出入口和视线；固定种子或显式稳定坐标，不每次 render 随机撒点。地面装饰和直立物分层，直立物按落点排序，不占用/覆盖可耕田、道路口和河口，不改变桥梁/水利关系 | 平移/重载后装饰不跳动，点击仍落到真实地块，树冠/建筑遮挡顺序正确；小地图不伪造规则对象 |

注：`ScenicWorldView.ts`、`ScenicStyleContract.ts` 位于 `assets/scripts/view/world/scenic/`；`tile-art.ts` 位于 `core/src/game/scene/`。泉眼、灌木等扩展还没有生产契约，本次 50 项交付不能把它们塞进现有 ID 充数；施工/设施的完整美术目录应按公开状态另行列出，而非用一张通用图假装全部支持。

道路走向仍受现有网格拓扑约束。第一轮通过路肩、转角内部和局部植被改善观感；若最终需要改变走向或田区密度，应作为单独布局任务评估点击、探索及水利关系，不能让图片作者偷偷变形端口。

## 8. 检查与最终完成条件

- 纯图片工作：尺寸、透明区、端口、落点、来源链、50 项完整导入及发布；A1 拼接检查、全包实际游戏核对各完成一次，只有修改或失败才追加相关检查。
- 修改生成/合成/发布工具：运行 `npm run test:tiles`，重点核对旧包兼容与接缝，不写仅重复配置值的测试。
- 修改场景核心：运行 `npm run core` 更新生成包，并运行 `npm run test:scene`；修改 UI 状态展示时运行 `npm run test:ui`。涉及运行时代码的最终接入执行 `npm run build` 并核对实际画面。
- 不把素材联系表、概念图或离线拼图称为游戏截图；不以“所有文件存在”或“构建通过”替代审美结论，不声称用户已认可。
- A 项完成后可交付独立新风格；B 项未完成时报告仍存在的雾、文字牌、布局与边缘问题。最终用户直接查看游戏，无须逐图批准。
