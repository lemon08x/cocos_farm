# 田园主场景：后续逻辑与问题解决方案

> 实施更新：已按后续确认建立统一场景系统，详见 [当前实现](scenic-scene-system.md)。用户明确取消旧存档兼容，并确认河流供水、桥梁探索和持续扩展；这些决定覆盖下文的旧档映射与装饰河流限制。下文保留为历史方案。

日期：2026-09-28。基准：`502d20a` 的 scenic revision-2。用户决定：将此版本作为主场景，后续逻辑根据此场景处理。

## 已执行：主场景入口

- 默认启动 scenic，版本列表优先展示田园场景。
- 场景偏好增加 schemaVersion 2；旧偏好首次升级到 scenic，镜头记录保留，游戏存档不变。
- 升级后主动选择旧版仍可记住。主场景资源加载失败时提示并临时回退，下次启动继续尝试原选择。
- current 保留为历史兼容视图；后续新功能以 scenic 为主，不要求为旧场景维护同等功能。

本次只实施默认入口和偏好迁移。以下为空间与逻辑整改方案，不表示已经修改游戏规则或完成这些问题。

## 1. 以主场景定义统一空间关系

保留当前院落、田区、河流、桥和主要道路布置，优先修正数据与行为，不再另起第三套地图。允许为实际重叠、连接或点击问题作局部调整，不以整体重画为前提。

建立不依赖 Cocos 的 SceneDefinition，描述区域 ID、类型、边界、邻接、连接口、交互能力和可选 plotId。静态场景定义与种植、探索、库存等动态状态分开。渲染器、命中、小地图、定位及后续空间规则读取相同定义。

规则核心不得导入 Cocos 组件。后续探索、地块邻接、水源覆盖和路径相关规则通过纯数据适配器读取主场景；具体能力以区域定义为准，不从贴图颜色或显示像素距离推断。

## 2. 环境占位隐藏地块：改成真实空间分配

问题：`isEnvironmentReservedCell()` 让房屋/河流占用的逻辑格跳过田况绘制，但地块和点击候选仍在。

解决步骤：

1. 将当前道路、河流、院落及桥登记为独立场景区域。这些区域不再隐含一块可耕田。
2. 列出与它们冲突的旧 plotId，给每个旧地块分配有效且独立的显示区域，保留 ID 与其作物、计划、设施等状态；采用明确映射表，不在每次启动时随机找空位。
3. 对后续探索，用场景拓扑决定可新增的田区和地块位置，环境区域不得再次生成可耕田。
4. 渲染和命中共同查询映射；删除“保留可点击地块但直接 return 隐藏”的处理。
5. 若未来需要改存档结构或规则坐标，单独版本化迁移，先备份并保留旧数据；不得删除冲突田块或通过新开局解决。

灌溉能力应显式标在真实水源上。当前装饰河流暂不自动获得灌溉能力；后续若赋予能力，由规则通过场景定义实现，地图、条件说明和实际行为同步。

## 3. 区域数据未接入运行时：改为单一来源

问题：目前 Region 主要参与检查，实际图片、道路、命中和小地图分别计算几何。

- 用 SceneDefinition 中的区域边界实际驱动田块渲染、选中轮廓和多边形命中。
- 道路按自身边界生成路面；边缘描边也计入区域范围，去掉检查多边形与实际粗线不一致的问题。
- 小地图、镜头定位使用区域中心与边界，不再单独套用旧的逻辑坐标公式。
- 保留规则布局生成器作为普通田区的默认来源，允许院前等重点区域使用明确布局数据覆盖。
- `ScenicProjection` 负责变换，`ScenicRegionLayout` 负责区域定义，`ScenicWorldView` 负责展示，互相不重复定义地块形状。

## 4. 固定网格限制：保留现有场景，增加局部布局能力

不因“仍是菱形”再更换整个主场景。普通田区沿用现有尺寸与方向；院落边缘、河湾、桥头及路口允许采用独立四边形或多边形区域。

不均匀位置通过稳定的 plotId → regionId 映射表达。点击使用候选区域的真实边界，不把旧投影反函数当成唯一结果。确保扩展时既能连续布置，也不会把已种植田地挪入环境区。

## 5. 检查绕过冲突：删掉豁免，检查真实数据

在真实映射接入后，取消对“环境预留格”的无条件跳过。只保留明确的桥跨河例外，并指定桥连接的河流及两侧道路。

必要检查只覆盖实际风险：游戏地块是否都有有效区域、是否与不允许的环境区域相交、点击是否返回对应 plotId、切换和迁移是否保留进度。删除仅重复常量或以中心点数量证明效果的断言，不建立新的验收框架。

## 6. 雾、地貌和设施状态：按真实区域表达

- 未探索雾层按未知区域边界生成遮罩或边界网格，不再把一张未知田块图放大覆盖整组地块。
- 可探索边界保留明确的选择反馈，未知地貌不泄露；探索后只更新对应区域。
- 补齐 `purpose`、`improvement`、`landscape` 等状态的地图表现及刷新标识，避免地块改成晒场或设施后仍显示空田。
- 作物、设施、缩略图使用统一状态映射，避免地图与 HUD 各自推导出不同结果。

## 7. 美术接入：按主场景补缺，不重新批量出图

- 已有可用资产继续使用。新增 AI 素材附带当前主场景、邻件和具体区域模板，按现有场景的视角与比例制作。
- 河流转弯补充所需方向，避免将带光照的岸坡整张旋转 180°。道路补充纹理和过渡，但必须服从真实区域边界。
- 土壤、田埂、作物共用轮廓和锚点；透明边缘、阴影和连接口随素材处理修正。
- 直立物按世界落地点统一排序，分块只负责加载，避免不同块的房屋/树木遮挡顺序错误。
- 保留源图和生成记录；不以导出成功、alpha 检查或联系表代替效果判断。

## 8. 实施顺序与交付

1. 主场景入口与旧偏好迁移（本次实施）。
2. SceneDefinition、冲突地块映射、实际区域渲染与命中同步接入，作为一个完整空间改动处理。
3. 小地图、定位、探索和后续空间规则统一读取定义；有存档变化时独立迁移。
4. 雾层、设施状态及必要美术补缺。
5. 构建并交付可运行主场景，说明实际完成内容和剩余限制。

不做阶段效果验收、自动评分或无关测试；实现完成后由用户亲自看效果。只做与本次改动直接相关的必要正确性检查。
