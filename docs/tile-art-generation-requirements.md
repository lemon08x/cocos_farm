## 1. 本次要交付什么

按现有 `tiles-v1` 契约完成 **50 个素材任务：43 张渲染源图 + 7 张公共接缝母版**。地面、道路、河流、桥都由完整四边形图片构成，像积木一样拼接；作物与直立建筑独立叠加。

使用所在环境可用的 AI 图片生成/编辑工具，并遵守其 skill 使用要求。允许依据存量素材审查加工复用；需要新内容时使用 AI 生成或编辑。不能用 SVG 色块、程序绘画、技术模板充当正式 AI 美术，也不能仅交付提示词就声称完成。若没有可用生成工具，明确记录能力缺口和未完成项。

本轮范围是可追溯、可导入的素材包。当前游戏仍使用 revision-2，完整 SceneCell 地图及新图块渲染尚未接入。不要为了展示新图而修改玩法、存档、地图布局或直接覆盖现有运行时素材包。

5. **原始美术目标**：[田区浏览参考图](../art/expansion-previews/02-district-browse.png)。实际查看这张图片，不能只读文件名或旧提示词。

参考图提供画风、材质、光照与元素尺度；模板提供需要严格遵守的几何和落点。不要照抄参考图中的 UI、文字或整幅构图。旧 `art/scenic/revision-2/SPEC.md` 只解释当前运行时包，不作为这次新图片的几何依据；旧图中有问题的透明轮廓和组合小岛不应继承。

开始时运行 `npm run tiles:status` 核对进度。此交接基线中正式源图为 0/50，已有文件都是技术模板。若另一个 agent 已补充来源记录，则从已有进度继续，不覆盖有效成果。

## 4. 图片必须满足的结构

- 地面源图 **600×360**，显示 **300×180**。菱形顶点为 `(300,0)、(600,180)、(300,360)、(0,180)`；内部画满、外部透明，不能留下缺半边的河流转角。
- 四边顺序是 `ul` 左上、`ur` 右上、`lr` 右下、`ll` 左下。路口居中占边长 **24%**，水口 **40%**。每张图必须遵守对应 job 的接口，接口外为草地，顶点附近保持简单。
- 道路与两侧草地属于同一张地面；河水、河岸与剩余草地也属于同一张地面。不能用单独的透明河道覆盖带替代完整单元。
- 母版 `edge.*` 为 **352×96**，`corner.grass` 为 **80×80**，均完整不透明。接缝母版的横轴沿单元边，纵轴跨接缝；道路/河水按模板占比居中上下贯通。它不是另一张透视小岛，模板中线不能画入成品。
- 作物画布 **600×360**，只画植物，行间透明，无土板。树木 **600×720**，根部落点 `(300,540)`；房屋 **1200×1080**，落点 `(600,540)`，只生成一栋占地 2×2 的完整农舍，无院落底板。
- 统一左上光照；禁止旋转带光影的图片补朝向。树干、柱子等直立结构保持竖直；屋顶、树冠和作物叶尖可伸出地面轮廓，不套地面裁切。
- 保持目标图的手绘田园感、清晰形体和疏密层次。避免密集高频草纹、厚土台、悬浮岛、硬黑框、边缘暗角、背景棋盘格、文字和 UI。

## 5. 复用与生成顺序

先完成 **7 张公共母版**，再生成草地、干湿田、院落、道路和河流；把已完成母版作为后续单元的材质参考。之后完成桥、独立房屋及作物。无需每一批都要求用户进行视觉验收。

可复用的原稿主要在 `art/scenic/revision-2/sources/`，对应原图和生成记录在 `generation-records/`：

- 树木保留主体，重新放置画布和根部落点。
- 两种幼苗保留主体，统一种植排列；456×284 图片可以补透明边到 600×360，不能拉伸填满。
- 干湿土壤可用于新地面的内部，与新草地外缘合成；整张原土壤图不能直接冒充完整地面。
- 成熟作物根据相同种植位置编辑/重生，避免与幼苗错行及整片不透底的厚块感。
- 房屋保留建筑形象，编辑成独立对象；原来的院子、树、围栏与底板不能一并带入。
- 河流、桥、草地按新要求生成；旧图只作材质或造型参考。
- 旧田埂框、旧整田雾图退出新地面包。UI 图标无需重画。保留全部旧版资产与记录。

技术模板应作为图像输入，而不只是把 prompt.txt 文本交给生成器。生成服务不能直接输出目标尺寸时，在较大画布中明确目标内容区域，再按已知矩形裁剪和等比缩放。不要让工具猜测居中裁边，不用非等比缩放凑尺寸。

## 6. 原图、处理过程与导入

每个 ID 留存生成原图、最终使用的提示词、参考图列表、实际生成工具/模型、裁剪及抠图/合成步骤。建议增加 `art/scenic/tiles-v1/generation-records/<id>.md` 保存工具记录以外的说明，可复现的加工脚本也放在该目录。不得记录凭据或临时授权 URL。

```powershell
# 更新模板仅从代码契约生成，不能手改模板来迁就不合格图片。
npm run tiles:prepare

# 比例正确的生成图片。
npm run tiles:normalize -- grass.0 "C:\art\grass.png" --generator "实际工具及模型"

# 明确裁剪区域的例子；不能不看原图就照抄此矩形。
npm run tiles:normalize -- edge.road.x "C:\art\edge.png" --generator "实际工具及模型" --crop 0,0,704,192

npm run tiles:status
npm run tiles:import
```

normalize 将输入原图按哈希保存在 `raw/`，将标准 PNG 写入 `sources/`，将工具、哈希、裁剪与规格摘要写入 `records/`。如果输入已经经过补边、抠图或合成，额外保存处理前原稿和全部来源链；normalize 的输入备份不能代替真正的 AI 原图。复用旧图时如实标注“复用 + 加工”及旧生成记录，不伪造新生成来源。

import 要求 50 个任务齐全并有有效记录，再用 AI 母版合成接缝，最后在 `build/tile-art/<包名-时间>/` 写入 43 张渲染图片和 manifest。它不会覆盖旧运行时包。`build/` 被 Git 忽略，正式交付必须保留可重新导出的 `raw/`、`sources/`、`records/` 和加工记录，不能只留下本机 build 产物。

不要修改哈希、注释掉校验或降低透明要求来让图片通过。若发现真实工具缺陷，可做最小修复并记录；如果需要改变尺寸、接口或目录，必须先更新权威契约并重新生成模板，不能默默绕过契约。公共接缝合成只统一边缘采样，不能自动修正画错的河道内部和不一致的画风。

## 7. 必要检查与最终交付

只完成有关图片可用性的检查：文件完整、尺寸及透明区、准确的接口方向、画布落点、来源链和一次最终导入。若修改工具，再运行对应的 `npm run test:tiles`；纯图片生成无需重跑游戏测试或 Cocos 构建。

不安排阶段截图评分、反复验收或用户逐图确认。全部完成后由用户亲自查看效果。最终可以提供一张素材总览和使用正式导出素材的道路/河流/桥拼接示意，标明这是素材预览，不能称为已接入游戏的场景。

交付 `art/scenic/tiles-v1/GENERATION-REPORT.md`，逐 ID 列出新增/复用方式、源文件、记录文件、缺失项与已知偏差，附最终导入结果及输出路径。未完成项必须明示；“有 PNG”“技术检查通过”都不等于用户已经认可画面。此任务不要求改动游戏逻辑或切换主场景；提交/推送按执行 agent 所在会话的用户指示办理。
