# 农场场景第二版整改方案

日期：2026-09-28。状态：待实施；本次仅提交方案。

目标：保留当前「田格手账」的布局和交互，新增接近参考图的「田园场景」版本。两个版本共用游戏规则、地块身份和存档，可在设置中切换。

视觉基准：[分区浏览参考图](../art/expansion-previews/02-district-browse.png)。旧版基线：[田格手账运行截图](../art/fieldbook/final-preview.png)。参考图中的资源数值、作物分布和待办数量仅说明表现形式，正式界面必须使用真实观察数据。

## 1. 已确认的问题与对应整改

| 问题 | 代码或素材依据 | 第二版整改 |
| --- | --- | --- |
| 正向矩形网格缺少参考图的斜向空间感 | `view/FarmDistrict.ts` 的横纵间距，`FarmWorldView.ts` 的矩形田块 | 保持逻辑坐标，新增独立投影和田块多边形 |
| 镜头较远，地块细节被缩小 | 默认缩放 0.82，地块绘制尺寸 202×152 | 新版默认近景，以主要田块与院落构成首屏；独立保存镜头偏好 |
| 环境变成重复底纹 | board 模式的 `background()` 提前返回，未使用 `board.environment` | 使用分块地景、独立院落、河岸与前景植被共同组成地图 |
| 水渠机械重复 | 按单元行列取模生成横竖水渠 | 使用有入口、出口和转弯连接的地景布局；桥与道路对齐 |
| 房屋覆盖院前田 | `boardTileSlot()` 优先将 p2q2 映射为房屋 | 房屋成为独立环境节点；p2q2 真实显示土壤、作物与选中状态 |
| 每块素材都有封闭边界 | `process-fieldbook-art.mjs` 裁切后统一拉伸为 512×384 | 新建专用素材流程，统一视角、比例、锚点；拆分田埂、田况、作物和遮挡 |
| 多数作物依赖图标表达 | board 模式主要提供小麦成长、成熟两种整块图 | 正式开放的作物具备可区分的成长、成熟表现，未知素材明确回退 |
| UI 与参考图不一致 | 细线图标、独立小卡片，缺少分区定位和待办提示 | 新增专用 HUD：资源条、分区定位、田况卡、实心导航图标 |
| 风格决定地图交互 | `groundMode` 分支散落在 HUD、地图和 FarmDemo | 新地图用独立模式入口，资源加载与镜头、命中、导航分别管理 |

## 2. 范围与约束

必须保持：

- 当前 fieldbook 及其他已存在风格仍能使用；现有用户默认保持原视图，新版先以显式选项提供。
- 地块 ID、逻辑坐标、每单元 3×3、邻接、探索、灌溉、行动报价和时间结算不变。
- 切换视图不创建新局，不推进日期，不改变资源、计划、命令记录或存档内规则。
- 新版院落不占用新增逻辑田块，不替换任何田块身份，也不新增生产能力。
- 当前启动脚本和构建变更独立处理，不与视觉整改混成同一提交。

本轮不做：农业核心拆库、人物与时代系统裁剪、整体存档迁移、3D 化、所有页面的 Prefab 重写。只抽取第二版实际需要的边界。

特别说明：旧存档使用自身的规则快照；视图切换必须读取同一会话。不能用“备份并新开局”解决视觉切换或验证问题。

## 3. 新版首屏的具体视觉目标

以 720×1280 设计尺寸建立初始构图，并在 390×844、430×932 和桌面竖屏容器验证。

- 顶部日期卡和资源条位于安全区内，合计约占画面高度 8%～10%。
- 底部田况卡与导航约占 27%～30%；中间地图为主要视觉区域，可延伸到 HUD 后方。
- 房屋与院落放在左上侧环境区，院前田位于中下部可操作区域；不让房屋贴图替代空田。
- 首屏主要突出 4～6 块可完整或大部分辨认的田，边缘允许露出相邻地块；无需把整个九格单元塞入首屏。
- 田块采用统一斜向俯视，田埂、作物行向、桥、道路和建筑底座服从同一视角。
- 用河流走势和连续植被形成场景层次。道路宽度、桥头位置和河岸边缘必须能在相邻区域连续对上。
- 选中描边沿田块轮廓显示；触摸区域与轮廓一致，不再套用正向矩形框。
- 日期、资源、状态文案与按钮使用清晰的字号和字重层级；导航使用深绿实心图标，选中项有独立标识。

以上比例是首轮布局约束，须结合实际运行截图调整。验收以构图和游戏内表现为准，不以概念图或脱离运行时的拼图替代。

## 4. 文件结构与模块边界

以下均为拟新增或迁移的结构，不代表已经实现：

```text
assets/scripts/
  FarmDemo.ts                         装配模块与连接页面入口
  presentation/
    FarmViewModel.ts                  将观察数据映射为地图/HUD所需数据
  view/world/
    FarmWorldViewContract.ts          地图接口与事件类型
    WorldViewRegistry.ts             视图工厂与可用版本
    MapInputController.ts            拖动、缩放、点击手势识别
    WorldViewPreferences.ts          视图、风格及各版本镜头偏好
    current/
      CurrentWorldView.ts             原地图实现，保留旧模式行为
      CurrentMapLayout.ts            原显示坐标与命中规则
    scenic/
      ScenicWorldView.ts             新版分层渲染与可见区域管理
      ScenicProjection.ts            逻辑坐标与世界坐标转换
      ScenicLayout.ts                院落、道路、河岸、田区布局
      ScenicHitTest.ts               多边形命中与边界处理
      ScenicChunkStore.ts            地景块缓存与卸载
  view/hud/
    ScenicHud.ts                     新版日期、资源、田况与导航
    DistrictNavigator.ts             田区入口、小地图与镜头定位

assets/resources/art-packs/scenic/   新版专用图集与清单
art/scenic/sources/                 分层源图与制作说明
art/scenic/reviews/                 同尺寸运行截图与对照记录
tools/process-scenic-art.mjs        新版专用素材检查与导出
```

旧的 `FarmWorldView.ts` 在第一阶段可保留为兼容入口，内部委托给 current 实现；确认调用方迁移完成后再清理。旧版 HUD 和 UiKit 可继续复用，不在第一阶段重写。

地图接口至少提供 `render(model)`、`hitTest(worldPoint)`、`focusPlot(id)`、`focusDistrict(id)`、`getCamera()`、`setCamera()`、`resize(viewport)`、`dispose()`。具体类型在第一阶段确定，禁止通过 `any` 传入整份 Session。

职责约束：

- FarmViewModel 接收核心导出的观察类型，输出明确的 PlotViewModel、HudViewModel 和任务摘要；集中处理田况与素材状态映射。
- 地图实现不提交规则命令、不读写游戏存档、不解析行动 ID；只输出选田、镜头变化等界面事件。
- 输入控制器识别手势，地图实现负责投影、命中和定位；新版不能继续调用旧版 `districtAtCamera()` 的横纵网格算法。
- HUD 接收展示数据与回调，不通过 `groundMode` 决定游戏业务行为。
- 场景布局与图片清单分离：布局记录锚点、轮廓和层次；图片清单记录资源、尺寸、裁切和主题。

## 5. 坐标、场景分层和扩展策略

### 5.1 同一逻辑世界，两套视觉坐标

保留 `p{x}q{y}` 和核心坐标函数。新版采用独立的可逆二维投影，将逻辑地块位置映射到斜向世界平面。首轮用两个不共线的基向量确定方向和间距，不把某个美术像素尺寸写入规则。

交互链路统一为：屏幕坐标 → 去除镜头平移和缩放 → 世界坐标 → 候选地块 → 多边形命中。自动定位、小地图视窗、描边和点击必须使用同一套变换。

院落作为独立地景锚点放置在主要可耕作区域外；无法避免的视觉覆盖通过场景布局调整处理，不删除或遮蔽可交互田块。

### 5.2 分层绘制

由下到上分为：基础地表与河床、道路与田埂、土壤与水分状态、作物、建筑与环境遮挡、选中描边及提示。建筑、作物和前景在适用时按落地点进行深度排序。

环境装饰不成为无意的触摸拦截层。树冠等前景若影响选田，需要调整布局或在选中时降低遮挡，不扩大隐形按钮掩盖问题。

干湿土壤和作物应能独立组合，避免将“水田”贴图中的幼苗当成真实作物。作物阶段依照公开观察中的真实状态渲染，不展示虚构成熟度。

### 5.3 区域与连续扩展

先完成院前，再完成东侧和南侧的相邻区域；院前、东侧、南侧是导航锚点，实际地块仍使用全局坐标。

地景块可以包含多个逻辑单元，不要求视觉分块边缘与九宫格边界重合。每种地景块声明道路与水道的边界连接点；选择变体时必须满足邻块连接约束。中心院落仅出现一次。

其他方向使用确定性地景变体补齐，避免重复房屋、河流断口和空白区域。视觉变体使用独立种子或坐标哈希，不消耗核心随机数、不改变探索结果。未探索区域仍遵守原规则，只显示未知地貌，不能从装饰泄露真实田况。

仅加载可见区域和一圈缓冲地景块；离开范围的节点与资源引用有明确释放策略。不能一次性绘制无限地图。

## 6. 美术资产制作要求

先制作可以在游戏中验证的院前区域，再扩充资产。完整参考图只作为构图基准，不能把它直接铺成包含固定作物和 UI 的背景。

首批交付：

| 资产组 | 必须提供的内容 |
| --- | --- |
| 统一视角基准 | 地块轮廓、道路宽度、建筑落地点、光照方向、尺寸标尺 |
| 院前地景 | 地面、独立房屋/院落、河岸、桥、围栏、前景树冠和花草 |
| 田地 | 可叠加的干土、湿土、空田和田埂；选中轮廓数据 |
| 作物 | 首轮以小麦成长/成熟验证层次，后续补齐客户端开放作物；明确缺失素材回退 |
| 相邻区 | 东侧与南侧的连接地景，至少覆盖河道直段、转角及桥头连接 |
| UI | 日期/资源图标、实心四入口、方向箭头、状态与待办标识 |

所有资产统一锚点、视角、光向和导出倍率。不得用 `fit: fill` 将不同透视素材强行拉成同一形状。源图可按目标显示尺寸约 2 倍制作，实际导出分辨率以清晰度和设备纹理预算确定。

新素材导出到 scenic 目录，不覆盖 fieldbook。导出脚本检查缺失资源、非法尺寸、透明边缘、锚点和布局引用；新增 Cocos 资源应提交对应 `.meta`。

## 7. HUD、导航与双版本切换

- 新版顶部采用日期卡加资源组；底部采用田况缩略图、名称、真实水分描述、真实待办和农事按钮。
- 缩略图显示选中田的实际状态，房屋不能替代田况图。
- 小地图来自已知地块和镜头位置，不能使用固定截图。展示当前视窗，支持院前/东侧/南侧定位；定位只移动镜头，不自动探索或执行行动。
- 分区导航不覆盖主要田块点击区；小屏可折叠，展开时明确拦截地图手势。
- 地图版本偏好使用新键 `shanju.cocos.world.v1`，不复用游戏存档键。旧风格偏好继续有效；新版资源选择限定在兼容的主题中。
- 切换时保留同一选田 ID，并分别记忆两版镜头。加载成功后再替换可见地图；加载失败保留原界面和会话，并允许重试。
- 连续切换时用请求序号或取消机制丢弃过期加载结果。销毁旧监听、节点、动画和资源引用，避免两套地图同时响应手势。
- 默认版本的最终变更另行决定；第二版完成前不自动替换现有用户视图。

## 8. 分阶段实施与交付门槛

| 阶段 | 具体工作与交付物 | 进入下一阶段的条件 |
| --- | --- | --- |
| P0：保存基线 | 为当前版本记录固定视口、选田、镜头、存档和运行截图；列出资源与偏好 | 可按记录复现旧版，同一输入获得同一田况 |
| P1：隔离地图实现 | 提取地图接口、旧实现适配器、ViewModel、输入边界与视图注册；补充类型 | 旧版布局和操作无回退，现有测试通过 |
| P2：院前灰盒 | 实现斜向投影、多边形命中、独立院落位置、首屏镜头与新版 HUD 骨架 | 房屋和田块比例、视角、主次接近参考；点击和定位准确 |
| P3：院前实景 | 接入分层地景、田况、小麦状态、植被遮挡和选中效果，完善 UI 视觉 | 导出同尺寸实际运行截图，与参考并排检查；主要视觉差距已解决 |
| P4：相邻区与切换 | 东/南区域、小地图、边界连接、其他方向回退、异步切换与资源清理 | 地图连续，旧/新版可往返，存档与行动结果一致 |
| P5：补齐与发布准备 | 补齐作物表现、安全区适配、性能测量、文档和构建验证 | 以下验收项全部完成，并明确记录实际测试设备 |

P2/P3 先解决院前画面的构图和素材融合，再扩展区域。每个阶段分别提交可运行代码与验证记录；若某项不通过，记录具体差距并在本阶段修正。

建议提交顺序：`refactor: isolate current farm world view` → `feat: add scenic projection and courtyard layout` → `feat: add layered courtyard art and scenic HUD` → `feat: connect scenic districts and view switching` → `test: verify farm view parity and rendering lifecycle`。

## 9. 验收标准

### 视觉与交互

- 同尺寸并排查看参考图和新版运行截图，检查斜向视角、近景田块比例、左上院落、河流连贯性、植被层次和底部信息层级。
- 验证空田、湿田、小麦成长/成熟、其他作物、未探索、选中和跨区等状态；主要田地不被房屋或 HUD 隐藏。
- 不出现明显贴片边缝、纹理拉伸、重复院落或河道断头。田块、道路、桥和建筑底座的投影方向一致。
- 点击田内、田埂边界、道路、重叠装饰区域，以及拖动/缩放后的相同位置，结果符合可视范围；拖动结束不误触农事。
- 使用指定三类视口验证文字、按钮、安全区和小地图，无裁切、重叠或不可点击入口。

### 规则与兼容性

- 同一存档在两版之间切换，游戏存档内容和 revision 不变；选田身份保持一致。
- 对同一初始会话执行相同行动序列，两版最终观察数据一致。
- 继续运行 `npm run test:ui`；增加投影往返、负坐标、多边形边界、分区定位和切换失败回退的针对性检查。
- 房屋与 p2q2 视觉分离后，院前田仍可正确安排计划、耕作和显示状态。
- 旧版无明显视觉回退；用 P0 相同数据、镜头和视口复核。

### 资源与性能

- `npm run build` 成功，产物实际加载 scenic 所需配置与图片；本地预览和静态构建都进行检查。
- 连续跨区浏览后，节点数和资源引用随可见范围收敛；切换地图版本 20 次后不出现持续增长或重复事件响应。
- 在记录了设备、浏览器和分辨率的目标手机上测量拖动表现。以稳定接近 60 fps 为优化目标，最低验收为交互期间稳定达到 30 fps；若无真机，标记未验收，不用桌面数据代替。
- 记录首次加载耗时、资源体积、节点与纹理规模，再决定是否合图、降采样或扩大缓存；不在无数据时设定硬性的缓存块数。

## 10. 文档与最终交付

实施完成后更新 `UI_ARCHITECTURE.md`、`ART_GUIDE.md` 和 README；将 `docs/farm-coordinates.md` 中的逻辑坐标约定与旧版显示约定分开，说明新版投影不改变规则。

最终交付应包含：可切换的两版地图、完整新素材源与清单、可重现的基线及新版运行截图、测试与设备记录、已知限制。发布说明须区分已经实现的区域和仍在使用回退资源的区域。

当前方案优先级：地图投影与首屏构图 → 独立院落与分层环境 → 田况和作物表现 → HUD → 区域扩展与性能。先让一个真实可玩的院前区域达到参考方向，再扩大地图覆盖范围。
