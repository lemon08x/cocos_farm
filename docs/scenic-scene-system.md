# 田园场景系统

当前场景：`scenic-farm`，版本 `1`。沿用 scenic revision-2 的主要布置。

## 数据流

`core/src/game/scene/` 是唯一场景来源：`geometry.ts` 管理纯几何，`layout.ts` 保存布局和美术锚点，`regions.ts` 构造固定环境边界，`world.ts` 提供有效地块、空间关系和快照。所有模块均不依赖 Cocos。

游戏状态保存场景标识和动态地块。初始化及探索通过场景查询生成地块；行动条件、执行和观察使用相同的农业邻接、探索连接及供水查询。`farm.scene` 将当前区域和连接传给视图；地块动态状态通过 `farm.plots` 提供。

前端的投影与布局模块是 `FarmCore` 导出的薄封装。地图、点击、选中、小地图和定位读取场景快照；分块装饰使用同一核心布局。不要在 UI 中重新推导探索、供水或设施作用范围。

## 区域和扩展

- 普通田区沿用当前尺寸；游戏地块仅出现在有效位置。道路外缘、院落地面、河源、河流和桥不生成游戏地块。建筑图片范围与地面占地区分。
- 区域及地块 ID 由坐标稳定生成。外围继续按 3×3 田区扩展，但一个田区的有效地块数量可以少于九块。
- 地图边界由实际已生成区域决定，镜头可跟随远方田地，不预生成无限地图。
- 固定环境不可选择或耕作；未知地块可以选中查看探索条件，不能提前知道资源。旧界面继续使用同一核心状态。

## 玩法关系

- 普通探索沿有效相邻田块展开。道路位于地块间，可跨越；未知田块不能作为通行中继。
- 两座现有桥分别连接 `p4q6 ↔ p4q8`、`p7q6 ↔ p7q8`。桥只提供探索连接，不传递设施覆盖或渠道供水。探索桥头会生成另一岸田区，可继续向外探索。
- 河流和河源水位为 `1`，可供同高或更低的邻田/渠道引水；发现泉眼仍需按原玩法疏浚。不会自动解锁科技、自动浇水或增加公共水库存。
- 手动灌溉优先使用已接通的河流、泉眼或渠道；未接通时使用公共水。开闸沿实际渠链向同高或低处传水，修复了原来渠道被当作普通田地导致渠链提前停止的问题。
- 排水必须有真实低处出口，或通过同高排水沟连到出口。河流水位低于排水沟才可排入；坐标轴不再视作出口。
- 晒场、种子窖和护田林按农业邻接计算；窝棚、田畔花园按农业邻接两步范围计算。农历中的晒场宽限同步使用同一关系。
- `spatial` 观察字段提供供水来源、排水结果和设施覆盖；“查看农事 → 水利与设施关系”展示规则结果。

## 显示与资源

道路按包含外缘的多边形绘制；地块与选中轮廓使用真实区域；雾层按未知区域生成遮罩。小地图同时绘制地块、道路、河流、桥及镜头范围。

设施、建设状态、地块用途和景观变化会触发地图与缩略图刷新。没有专用图片时使用名称标识；本次复用已有素材，没有重新批量生成 AI 美术。直立树木、建筑与设施在同一层按世界落地点排序，分块仅管理环境节点生命周期。

## 存档与启动

用户已决定放弃旧进度。启动时只删除旧游戏键 `shanju.cocos.farm.v1`；新版使用 `shanju.cocos.farm.v2`，保存 `{ id: 'scenic-farm', version: 1 }`。场景偏好和美术设置保留。

首次创建新版进度显示重新开局提示。已有 v2 正常读取；损坏或未知场景版本保留原内容，进入禁止覆盖原档的临时局并显示错误，不自动重置 v2。

修改核心后运行 `npm run core` 生成客户端规则包；正式交付运行 `npm run build`，启动脚本使用构建指纹避免运行旧输出。

## 必要检查

`npm run test:scene` 覆盖实际地块与环境边界、桥和扩展、水位及渠链、排水、设施范围、动作与存档、旧键清理和小地图数据。`npm run test:ui` 覆盖现有界面数据和交互工具。

不安排自动视觉评分或阶段截图验收。最终画面由用户亲自查看。
