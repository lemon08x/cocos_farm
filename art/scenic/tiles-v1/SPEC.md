# 四边形拼接素材规范 v1

本目录实现 AI 素材的生产契约、构图模板、来源登记与接缝合成。**模板是技术示意图，不是正式美术。当前运行中的游戏仍使用 revision-2 素材包。** 此阶段先固定图片规范，尚未将连续道路、河流转换为完整的单元地图。

查看 [模板目录](index.html) 或 [九格拼接示意](assembly-guide.png)。九格图中的颜色和桥面符号只表示位置，不代表目标画风。

## 1. 唯一规格来源

`core/src/game/scene/tile-art.ts` 定义画布、四边接口、素材家族、占地、锚点和版本。工具据此生成目录与说明，禁止手改生成的 catalog/job 文件代替修改契约。

```text
场景单元数据：坐标、区域类型、plotId、四边连接
          ↓ 选择素材家族与四边接口
tile-art.ts：尺寸、接口、图层、占地、稳定变体选择
          ↓ prepare
每张素材的 control.png + guide.png + prompt.txt + job.json
          ↓ AI 生成并保留原图
normalize：明确裁剪、等比缩放、透明区检查、来源记录
          ↓ import
共用 AI 接缝母版 + AI 单元内部 → 完整地面 PNG
          ↓ 待后续地图适配完成
Cocos 读取清单，以单元坐标摆放图片与独立上层物体
```

图片不决定玩法。草地图可以对应未知地块、荒地或装饰单元；道路和河流单元不创建 FarmPlot。桥的道路连接、水流连接分别记录，不能由同一张桥图片推导为农业邻接。

## 2. 地面必须覆盖整个单元

| 项目 | 固定值 |
|---|---|
| 基础形状 | 等距投影的菱形，禁止任意四边形各自变形 |
| 游戏显示尺寸 | 300 × 180 |
| 素材画布 | 600 × 360 PNG，2 倍分辨率 |
| 四个顶点 | (300,0)、(600,180)、(300,360)、(0,180) |
| 原点 | (300,180)，画布中心 |
| 透明要求 | 菱形内画满，菱形外透明 |
| 光照 | 左上光、右下短影，各方向单独生成，不旋转图片复用 |
| 内部耕作区 | 可小于单元，但外缘草地必须属于这张地面图 |

禁止厚土台、悬浮岛、底座、边框、黑边和独立矩形背景。道路图同时包含道路与两侧草地；河流图包含河水、河岸与剩余地面，不能只生成一条透明河流覆盖带。最终所有基础地面都由图片铺满。

当前布局里 228 × 142 的内田不是完整地面尺寸，不能继续把它当作拼接单元。

## 3. 四条边就是模块接口

边名描述屏幕位置；编号顺序固定为 ul、ur、lr、ll，对应掩码 1、2、4、8。

| 边 | 相邻单元坐标增量 | 对方接口 | 共用母版方向 |
|---|---|---|---|
| ul 左上 | (-1,0) | lr | x |
| ur 右上 | (0,-1) | ll | y |
| lr 右下 | (+1,0) | ul | x |
| ll 左下 | (0,+1) | ur | y |

每条边只能声明 grass、road、river 之一：草地接草地、路口接路口、水口接水口。路口居中占边长 24%，水口占 40%，其余边段为草地。此版本不支持同一条边同时出现两条路或路水并列；有这种需求必须增加接口类型及版本。

例如 `bridge.ul-lr` 的左右上/下边声明为 `ul=road, ur=river, lr=road, ll=river`。它将一个完整基础单元同时画成河流与跨河桥面。桥头必须接 road 边，不能直接接 grass 边。

缺少匹配的素材直接报错，不能拿普通田块或拉伸图片填空。草地变体按坐标确定，重新加载不会随机换图。

## 4. 接缝不能只靠提示词

独立 AI 出图无法保证相邻像素一致。因此新增 7 张也由 AI 生成的公共小图：grass/road/river 各自的 x、y 方向接缝母版，共 6 张 352 × 96 PNG，以及 1 张 80 × 80 草地顶点母版。

接缝图使用局部坐标：水平方向沿单元边，竖直方向穿过接缝；中间横线代表实际接缝但不绘入成品。道路或河水位于水平中点，贯穿母版上下，左右为草地。生成工具不适合此长宽比时，可以在更大画布按明确区域生成，再使用 `--crop` 指定该区域。

合成器让相邻两张图使用**同一张母版的不同半边**：地面内侧 16 个源像素完全锁定为母版，接下来的 16 像素与单元内部混合；顶点附近同样使用共享草地母版。整个正式地面的像素来自 AI 单元图和 AI 母版，代码只负责采样、透明蒙版和混合，不用程序色块替代正式道路或河流。

这能约束连接位置与接缝来源，但不能保证 AI 河岸、内部材质和母版过渡自然。机器检查不判断画风或理解河水语义；这部分由用户在完整实施后查看。模板中的路口位置是真实几何边界，不能把 AI 绘偏的路口当作自动合格。

## 5. 作物与建筑独立叠加

| 图层 | 画布与锚点 | 内容 |
|---|---|---|
| ground | 600 × 360，中心锚点 | 草地、干/湿田、院落、道路、河流、桥 |
| crop | 600 × 360，中心锚点 | 作物主体，行间透明，生长阶段共用种植位置 |
| object.tree | 600 × 720，落点 (300,540) | 树木，顶部预留树冠空间 |
| object.house | 1200 × 1080，落点 (600,540) | 一栋占地 2×2 的完整房屋，屋顶可向上伸出 |

清单中的 origin 与 anchor 使用**图片左上角为原点、y 向下**。Cocos UITransform 使用左下角锚点时需转换为 `(anchor.x, 1-anchor.y)`，避免树木错位。

房屋的四个单元是占地，不是四栋独立建筑。树冠、屋顶、作物可向上伸出地面菱形，不能对上层物体套用地面裁切。对象按世界落地点排序；不能把整个加载分块当成一个深度组。

用途、施工、设施状态另由规则观察数据驱动。此首批目录只有树、房屋和两种作物的两个阶段，**不是全游戏设施美术已经齐全**。以后增加对象条目时沿用占地/落点规范；玩法仍不需要为每个生长阶段复制地面图。

## 6. 首批素材目录

- 地面 37 张：3 张草地、干/湿田各 1、院落 1、道路 15、河流 14、桥 2。
- 作物 4 张：小麦与通用作物，各有生长和成熟状态。
- 上层对象 2 张：树、农舍。
- 公共母版 7 张：6 张接口、1 张顶点。

共 **50 个生成任务，最终渲染素材 43 张**。道路包括四向端头、直线、转弯、三通、十字；河流不包含四向十字水口。河源/水潭使用单口封闭模块。没有专用贴图的季节/设施变化不能伪装成已经支持。

## 7. 文件及命令

```text
art/scenic/tiles-v1/
  SPEC.md                 人可阅读的规范
  catalog.json            从 TypeScript 契约生成的完整任务目录
  index.html              可浏览模板目录
  assembly-guide.png      九格技术拼接示意
  jobs/<素材ID>/
    job.json              画布、图层、接口、占地与模板哈希
    control.png / .svg     无标注构图模板
    guide.png / .svg       带边名/落点的说明模板
    prompt.txt            当前素材的 AI 生成说明
  raw/                    保留生成原图，以 SHA-256 命名
  sources/                normalize 后的 PNG
  records/                生成工具、原图哈希、裁剪及契约版本
build/tile-art/<包名-时间>/  全部通过导入后产出的图片与 manifest
```

```powershell
npm run tiles:prepare
npm run tiles:status
npm run tiles:normalize -- grass.0 "C:\art\grass.png" --generator "实际使用的工具和模型"
npm run tiles:normalize -- edge.road.x "C:\art\road-edge.png" --generator "实际使用的工具和模型" --crop 0,0,704,192
npm run tiles:import
```

normalize 拒绝比例不符的图片，必须明确提供裁剪区域；只有比例相同才等比缩放。检查地面内部缺口、地面外绘制、母版不透明、上层实际透明背景；技术模板本身不能登记为正式生成图。它不会自动抠掉悬浮侧壁、删除错误背景或猜测主体位置。

import 检查 50 张图及来源记录，合成接缝，最后写入可用清单。缺图、过期规格、源图被手动修改都会报错；不会替换运行中的旧素材包。生成原图和来源记录保留，不能只交付导出的 PNG。

## 8. 接入地图的下一步边界

必须建立覆盖地面全域的 `SceneCell`：坐标、区域归属、可选 plotId、素材家族和接口。道路、河流、院落和桥也占用基础单元；现有连续多边形只负责转换时的布局参照，不能与新单元并存为两套空间真相。

先将当前院落、田区、河流走向、桥位置映射到统一格网；格网不能精确表示的连续曲线需要按单元调整轮廓。桥的两岸入口、地块关联、探索/水流/农业连接必须随映射更新，不能只换图片。最后地面渲染、命中、小地图、镜头与雾层都读取这些单元，建筑/作物叠层读取规则状态。

此文档不声称以上运行时转换已完成。本次交付的是这一转换前需要固定、可执行的图片规范和生产工具；当前启动脚本不会展示模板组成的假成品。
