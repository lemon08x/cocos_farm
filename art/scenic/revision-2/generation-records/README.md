# 生成记录（generation-records）· revision-2

每个正式素材（含场景标准图）对应一份记录文件，保证源图 → 导出图 → 游戏内表现可追溯。依据[第二版纠偏与实施计划](../../../../docs/farm-scene-v2-recovery-plan.md) §6.4：保存原始文件、生成参数/提示词、所用参考、裁切与处理步骤；**禁止覆盖唯一原稿**。

## 目录结构

- `raw/`：AI 生成的**原始文件**（未经裁切/抠图/缩放的唯一原稿）。文件名带版本后缀（如 `courtyard-standard-v1.png`）；返修产生新文件（`-v2`…），不覆盖旧文件。
- 每个槽位一份 `<slot-or-name>.md`（如 `field-soil-dry.md`、`courtyard-standard.md`），与 `raw/` 同级。

## 记录文件格式

每份 `.md` 使用以下小节（标题可中文，字段名保持一致）：

```markdown
# <槽位或素材名>

- 槽位：<slot id，如 field.soil.dry；标准图写 standard>
- 日期：<YYYY-MM-DD>
- 状态：<候选 | 已接入 | 已替换 | 废弃>

## 最终提示词
<实际生效的完整提示词原文；含参考图清单与排除项>

## 原始文件
- 路径：raw/<filename>
- 原始尺寸：<W×H>
- 生成工具：<工具与版本，如 codex-cli image_gen>

## 后处理步骤
1. <按顺序列出：裁切坐标、缩放倍率、抠图方式与参数、边缘清理等；无则写“无”>
2. 产物路径：../sources/<kebab>.png（进入导出管线的源图）

## 验证结果
- 尺寸/宽高比：<实测 vs 模板要求>
- alpha 检查：<四角/中心/不透明，实测值>
- 组合检查：<与相邻素材在显示尺寸下的套合、接缝、光向结论；未做则写明>
- 结论：<通过导出脚本校验 | 待复测 | 不合格原因>
```

## 规则

- 提示词以**最终生效版本**为准；中间试错版本不必逐条保留，但返修原因写入“后处理/验证”。
- 任何裁切、缩放、抠图都必须记录在“后处理步骤”，使 `raw/` 原稿可复原推导。
- 验证结果以 `tools/process-scenic-art.mjs` 的实际输出为准，不写“应该能通过”。
- 返修迭代在原记录追加小节（保留历史），新原稿进 `raw/`。
